# Spotify local reference observation

Measured on 2026-09-24 local time with Spotify 1.3.0.277 and macOS 26.6.2 (25G83).
Spotify preserved our complete original five-second reference through its process-specific BlackHole tap for WAV, ALAC, and FLAC playback.
Each run compared all 220,500 stereo frames and 441,000 Float32 sample words exactly, including the first and last frames.
These are local-file measurements at a software boundary, not evidence of subscription-master identity or delivery inside a DAC.
The shipped beta.2 application is unchanged.

## Fixtures and measurement boundary

The three files contain the same deterministic, quiet 44.1 kHz stereo 24-bit reference generated by `filo_test_sample`.
The [fixture manifest](../validation/spotify-reference-fixtures.json) records the original file hashes, container metadata, and independent packed24 and Float32 decodes.
Before each capture, the helper independently decoded the selected file with AVAudioFile and checked every sample against both the canonical WAV and the generator.
The same frozen helper source and executable were used for all three captures.
Their identities and linked objects are documented with the [exact source and reproduction procedure](experiments/spotify-reference/README.md).

The captured path was:

```text
Known local WAV / ALAC / FLAC
  -> Spotify 1.3.0.277
  -> process-specific Float32 tap pinned to BlackHole 2ch at 44.1 kHz
  -> bounded in-memory capture and complete-reference comparison
```

The tap used `relay: false`.
Neither filo's exclusive relay nor a physical DAC output was opened.
WALKMAN was absent from the live device list during these runs, and BlackHole was already the default output at 44.1 kHz with its Internal Fixed clock.
This was a fresh baseline, different from the earlier WALKMAN experiments.

## Player controls and procedure

Spotify's volume was 1, repeat and shuffle were off, and visible settings showed normalization, equalizer, mono, and crossfade off.
Gapless and Automix remained on; these observations do not claim that every possible processing control was disabled.
Autoplay was temporarily disabled, and the existing Downloads and My Music sources were temporarily excluded.
Only the folder containing the three original synthetic files was added.
All three codecs appeared as five-second local tracks.

For each run, the Local Files search was filtered to the selected codec, leaving one result.
The helper armed before playback, and the UI showed the selected fixture playing with an empty queue.
It returned to a paused state after playback.
Each capture window was 30 seconds, leaving ample measured silence before and after the reference.
No subscription audio was recorded, and no unrelated file was selected for playback.

All runs reported zero missing reference frames, extra nonzero prefix or suffix samples, invalid buffer layouts, non-finite values, and samples outside the 24-bit integer grid.
Every reference Float32 bit pattern matched; no gain fitting, rounding, resampling, or partial-window acceptance was used.
The complete reference span in all three captures has SHA-256 `f8277734d6e03b38d497bc2397fed81e470cec581a9c564081d7a1db412ae428`.

An [independent offline analysis](../validation/spotify-reference-analysis.json) manually decoded the original signed24 RIFF data, located three disjoint byte anchors, and compared every Float32 word at a single fixed offset.
Its ten controls cover an exact padded reference and failures involving missing endpoints, endpoint replacement with silence, extra active material, an internal dropped frame, a sub-LSB change, and a changed zero sign bit.
The [analyzer source](experiments/spotify-reference/analyze-spotify-reference.py) is archived with the measurement helper.

## What this changes

The tested Spotify local-file path can deliver the complete reference unchanged to this tap boundary.
Unlike the earlier [Music observation](music-reference-observation.md), these captures contain no altered opening or off-grid rounding residue.
That difference applies to these player versions, fixtures, and settings; it does not establish that subscription playback uses the same decoder and processing path.
The passing Spotify source measurement and the earlier passing exclusive bridge measurements must not be combined into an unmeasured Spotify-to-DAC claim.
The next hardware experiment must measure that connected path in one run.
That subsequent [connected experiment](spotify-exclusive-observation.md) now records complete passing replays and failing first switches at the WALKMAN software output callback.
Its different route baseline and additional physical-output stages are documented separately; it does not change these source-only measurements.

Spotify's current [exclusive-mode documentation](https://support.spotify.com/us/article/exclusive-mode/) lists Windows Desktop support, not macOS support.
It does not provide a native macOS integration path or specify per-track DAC sample-rate and bit-depth negotiation.
The documented [lossless quality](https://support.spotify.com/us/article/audio-quality/) reaches 24-bit/44.1 kHz; that describes source availability rather than the exact physical output format.

The tap-only metrics do not expose callback timestamp continuity or stop/destroy return statuses.
The receipts explicitly mark timestamp evidence unavailable.
Complete byte equality proves the captured finite sequence; it does not independently establish all callback timing or teardown properties.
No USB payload, receiver input, analog output, or subscription master was observed.

## Restoration

All three helpers exited and reported no route-restoration errors.
Independent before/after device-list and BlackHole clock snapshots were byte-identical, and no task capture process remained running.
Autoplay, Show Local Files, Downloads, and My Music were restored to their original preferences.
The test source was disabled and its tracks removed from the active Local Files selection.
Spotify retained its disabled custom source entry; no selective row-deletion control was found, and no user catalogue database was cleared.
All other player controls remained unchanged.
Raw synthetic captures and original fixture files remain locally under ignored `work/`; the public artifacts contain code, hashes, and measurement statistics.
